## 2026-11-19 ~19:20–20:05 — Phase 2: logic loop + game-state machine

Design decisions:
- **Deterministic fixed timestep.** The VBlank ISR queues one input sample per retrace. Each game
  frame consumes exactly `R_UPDATE_RATE` samples and applies the original per-retrace pad
  accumulation (`PadMgr_UpdateInputs` logic) to each. Frame inputs therefore depend only on the
  per-VBlank input sequence, not on compute time. That's the basis for Phase 8 replays.
- **Header strategy.** `tools/import_header.py` copies original headers and swaps `ultra64.h` for a
  scalars-only `game_types.h`, so every platform type surfaces as a compile error and gets fixed
  by hand. The import cascade pulled in `ultra64/gbi.h` once; I deleted it and adapted `light.h`
  and the `transition*.h` headers instead (native light record, native draw signatures).
- `bzero`/`bcopy` call sites are rewritten to `memset`/`memmove` (no macro shim).
- The system arena is native newlib `calloc` (zero-filled, so behavior never depends on stale RAM).

## 2026-11-19 ~20:10–21:30 — Phase 3b: offline DL compiler, exact math layer, skeletal animation

- **`tools/dl2gx.py`**: an offline F3DEX2 display-list compiler (vertex cache, tile/texture/TLUT state,
  combiner classification, geometry mode, segment-0x0D skinning matrices → GX `MTX_RESTORE`).
  Validated against the independent OBJ exports: **36/36 (child player), 43/43 (adult player),
  13/13 (gameplay_keep) DLs match triangle counts exactly.**
- **Exact numeric layer** (`game/math/*`, `exact_math.c`): the game's own `sinf/cosf` (double
  polynomial), `sins/coss` table, and fp.s rounding helpers (which go through s32; `roundf` is
  floor(x+0.5)) are ported bit-for-bit. `-fno-builtin-sinf/cosf` stop GCC from constant-folding them
  with libm. Call sites are renamed `Exact*` by the importer.
- **Gameplay-visible matrix quantization found:** `viewProjectionMtxF` (actor culling, screen
  positions) is rebuilt from the s15.16 fixed-point view matrices (`z_play.c:1211`). Reproduced
  exactly with a game-side `MtxQ` integer matrix (`Matrix_MtxFToMtxQ` / `Matrix_MtxQToMtxF`). No
  platform matrix type is involved.
- **Asset handles**: symbols become `ASSET_TOKEN(0x80000000 | segAddr)`. Bit 31 avoids colliding
  with DS RAM (0x02xxxxxx = segment 2). Converted records carry relocation lists, so intra-asset
  pointers become real pointers at load. `SEGMENTED_TO_VIRTUAL` call sites become `Asset_Resolve`.
- **Flex skeletons**: the original builds all limb matrices before the RSP draws (meshes can use
  matrices of later limbs). Natively, pass 1 is the adapted game traversal (all logic and
  callbacks unchanged) recording matrices. Pass 2 stores them to GX stack slots and draws with
  `MTX_RESTORE`.
- Player animation frames (2.5 MB file) are streamed from NitroFS per frame, read synchronously at
  task creation (the original's async DMA). Logged as an equivalence assumption.
- The game's own arena allocator (`libc64 __osMalloc`) is ported with the N64 0x30-byte node header
  (static-asserted), so actor-heap exhaustion behavior is preserved.
- Bugs I caused and fixed: a backspace byte (0x08) injected into a regex by a shell heredoc broke the
  importer for ~15 min. `apply_exact.py` renamed primitives inside `exact_math.c` itself (infinite
  recursion, caught by `-Winfinite-recursion`).

## 2026-11-21/22 — 3DS P2 (part 1): offline display-list compiler + PICA200 renderer

  mode, combiner, prim/env/fog/blend colours, texture bindings for TEXEL0 and TEXEL1 with tile

  offline into native enums (`source/engine/pmesh.h`). TMEM loads are tracked by address (LOADBLOCK and
  LOADTILE rectangles, TLUT banks); textures become PICA formats without loss of channels

- Render-state presets: the 71-entry `sSetupDL` table (behind `Gfx_SetupDL_*`) was located in the ROM
